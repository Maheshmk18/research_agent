# Research Agent API

A FastAPI-based multi-agent research backend that:

- creates a research plan for a topic
- searches the web for supporting sources
- writes a draft report
- fact-checks and improves the report
- stores reports in MongoDB
- stores report vectors in Pinecone for semantic search
- traces workflows with LangSmith

This project is useful if you want to build an AI research assistant backend with a clear pipeline and API endpoints.

## Overview

The system takes a topic like `AI in Healthcare` and runs it through a small agent workflow:

1. `Supervisor Agent` creates a research plan
2. `Search Agent` fetches web sources using Tavily
3. `Writer Agent` generates a draft report
4. `Fact Checker Agent` improves and verifies the draft
5. The final report is saved in MongoDB
6. The final report is embedded and stored in Pinecone

Later, you can search saved reports semantically using the `/research/search` endpoint.

## Tech Stack

- `FastAPI` for the backend API
- `LangGraph` for workflow orchestration
- `LangChain` for prompt + model pipelines
- `Groq` for LLM inference
- `Tavily` for web search
- `MongoDB` for document storage
- `Pinecone` for vector storage and semantic search
- `LangSmith` for tracing and observability

## How It Works

### 1. API entrypoint

The app starts from [main.py](/d:/Agent/research_agent/main.py:1).

It creates the FastAPI app and registers:

- `research_router`
- `history_router`

### 2. Research workflow

The main workflow is defined in [graph/research_graph.py](/d:/Agent/research_agent/graph/research_graph.py:1).

The steps are:

#### `plan_node`

- receives the topic
- calls `run_supervisor(topic)`
- saves the generated plan in MongoDB

#### `search_node`

- builds a search query like `"{topic} latest research"`
- fetches sources from Tavily
- saves source data in MongoDB

#### `writer_node`

- sends the topic, plan, and sources to the writer model
- generates a draft report

#### `fact_checker_node`

- reviews the draft report with the sources
- returns an improved final report
- saves the report in MongoDB
- creates an embedding vector
- stores the vector in Pinecone

### 3. Semantic search

The `/research/search` endpoint:

- embeds the search query
- searches Pinecone for similar report vectors
- reads matched report documents from MongoDB
- returns ranked report matches

## Agents

### `agents/supervisor.py`

Creates a step-by-step research plan for the topic.

### `agents/search_agent.py`

Uses Tavily to search the web and collect source snippets.

### `agents/writer_agent.py`

Uses the plan and source data to generate a draft report.

### `agents/fact_checker.py`

Reviews the draft and sources, then returns a cleaner and more verified final report.

## Database Design

MongoDB stores four collections:

- `plans`
- `raw_data`
- `reports`
- `agent_logs`

### `plans`

Stores the research plan generated by the supervisor agent.

### `raw_data`

Stores Tavily search results and collected sources.

### `reports`

Stores:

- topic
- draft report
- final report
- status
- Pinecone id
- word count
- timestamps

### `agent_logs`

Stores workflow logs such as:

- which agent ran
- started/completed/failed status
- input and output
- timestamps

## Pinecone Usage

Pinecone is used to store report vectors so reports can be searched by meaning instead of exact keywords.

The current code expects a Pinecone index named by:

```env
PINECONE_INDEX_NAME=research-reports
```

### Recommended Pinecone index configuration

When creating the index in Pinecone, use:

- `Name`: `research-reports`
- `Vector type`: `Dense`
- `Dimensions`: `1536`
- `Metric`: `Cosine`
- `Deployment`: `Serverless`

If the index does not exist, the API will raise a clear error message.

## API Endpoints

## `GET /`

Health check endpoint.

### Response

```json
{
  "message": "Research Agent API is running"
}
```

## `POST /research/create`

Runs the full research workflow for a topic.

### Request body

```json
{
  "topic": "AI in Healthcare"
}
```

### Success response

```json
{
  "topic": "AI in Healthcare",
  "status": "verified",
  "message": "Research saved successfully with id <report_id>"
}
```

### What happens internally

- validate topic
- run LangGraph workflow
- generate plan
- search sources
- write draft
- fact-check draft
- save report to MongoDB
- save vector to Pinecone

## `POST /research/search`

Searches saved reports semantically.

### Request body

```json

  "query": "AI diagnosis tools in hospitals",
  "top_k": 5
```

## `GET /history`

Returns all saved reports from MongoDB, newest first.

## `GET /history/{report_id}`

Returns one report by MongoDB id.

### Possible errors

- `400` if the report id format is invalid
- `404` if the report is not found

## Setup Instructions

### 1. Clone the repository

```powershell
git clone https://github.com/your-username/research_agent.git
cd research_agent
```

### 2. Create a virtual environment

```powershell
python -m venv .venv
.\.venv\Scripts\activate
```

If `python` is not working properly on Windows, use the interpreter from your virtual environment directly after creating it.

### 3. Install dependencies

```powershell
pip install -r requirements.txt
```

### 4. Configure `.env`

Add all required API keys and database settings.

### 5. Create the Pinecone index

Create an index named `research-reports` with:

- `Dense`
- `1536 dimensions`
- `Cosine`
- `Serverless`

### 6. Start the server

```powershell
python -m uvicorn main:app --reload
```

### 7. Open Swagger UI

Visit:

```text
http://127.0.0.1:8000/docs
```
